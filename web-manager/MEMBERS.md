# ผู้ใช้และผู้ดูแลร่วมของรายการแข่งขัน

## ติดตั้ง

1. สำรองฐานข้อมูล แล้วรัน `supabase/migrations/010_competition_members.sql` ใน SQL Editor ของโปรเจกต์เดิม หลัง migration 009 ไฟล์นี้ทำงานเป็น transaction และไม่ย้ายเจ้าของหรือลบข้อมูลเดิม
2. Supabase → Authentication → Sign In / Providers: เปิด **Allow new users to sign up**, เปิดผู้ให้บริการ Email และเปิด **Confirm email** การยืนยันอีเมลเป็นเงื่อนไขสำคัญของสิทธิ์ที่เชิญด้วยอีเมล ต้องเปิดก่อนใช้งานการเชิญ
3. Authentication → URL Configuration: กำหนด Site URL เป็น `https://arreef45.github.io/obs-scoreboard/manager/` และเพิ่ม Redirect URL `https://arreef45.github.io/obs-scoreboard/manager/index.html` โดยคง URL ตั้งรหัสผ่านเดิมไว้
4. ตรวจว่าบริการส่งอีเมลของโปรเจกต์ส่งอีเมลยืนยันให้ผู้ใช้จริงได้ หากจำกัดผู้รับ ให้ตั้ง Custom SMTP ตามเอกสาร Supabase
5. เผยแพร่ไฟล์ build ใน `manager/` จาก PR นี้ แล้วทดสอบกับบัญชีอีกคนก่อนใช้งานจริง

เอกสารทางการ: [Email/password authentication](https://supabase.com/docs/guides/auth/passwords), [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls), [SMTP](https://supabase.com/docs/guides/auth/auth-smtp), [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)

## วิธีใช้

- ผู้ใช้ใหม่กด **สมัครสมาชิก** ยืนยันอีเมล แล้วเข้าสู่ระบบเพื่อสร้างรายการของตัวเอง
- เจ้าของรายการกด **ผู้ดูแลร่วม** ที่การ์ดรายการ แล้วระบุอีเมล ผู้ใช้ที่ยืนยันอีเมลแล้วได้รับสิทธิ์ทันที
- ถ้ายังไม่มีบัญชีหรือยังไม่ยืนยันอีเมล จะอยู่ในรายการรอ เจ้าของคัดลอกลิงก์สมัครไปส่งให้เอง ระบบไม่ได้ส่งอีเมลเชิญอัตโนมัติ
- เมื่อผู้รับสมัคร ยืนยันอีเมล และเข้าสู่เว็บ ระบบรับคำเชิญตามอีเมลที่ยืนยันใน Auth ไม่อ้างอิงอีเมลจาก metadata ที่ผู้ใช้แก้ไขเองได้
- เจ้าของถอนสิทธิ์หรือยกเลิกคำเชิญได้จากหน้าผู้ดูแลร่วม ผู้ดูแลร่วมเพิ่มคนอื่นหรือแก้สิทธิ์ตนเองไม่ได้
- สิทธิ์แยกตามรายการ/รอบ ไม่ส่งต่อไปยังรอบย่อย รายการอื่น หรือฤดูกาลใหม่อัตโนมัติ

## ขอบเขตสิทธิ์

| งาน | เจ้าของรายการ | ผู้ดูแลร่วม |
|---|---|---|
| ดูรายการและทีมที่เข้าร่วม | ได้ | ได้ |
| แก้รายละเอียดรายการ จัดโปรแกรม รายชื่อผู้ลงแข่ง ผล และเหตุการณ์ | ได้ | ได้ |
| บันทึกผลจาก OBS | ได้ | ได้ |
| ยืนยันทีมเข้ารอบ | ได้ | ต้องมีสิทธิ์ทั้งรอบต้นทางและปลายทาง |
| เพิ่ม/ถอนผู้ดูแลร่วม | ได้ | ไม่ได้ |
| ลบรายการ เปลี่ยนเจ้าของ เปิดสาธารณะ หรือโครงสร้างแม่/ลูกและฤดูกาล | เจ้าของลบ/เปิดสาธารณะ/แก้โครงสร้างได้ แต่เปลี่ยนเจ้าของไม่ได้ | ไม่ได้ |
| คลังทีมและนักเตะ | ผู้สร้างทีมแก้ได้ | อ่านทีมที่เข้าร่วมได้ การแก้คลังสงวนให้ผู้สร้างทีม |

คลังทีมอาจใช้หลายรายการ จึงไม่ให้ผู้ดูแลรายการหนึ่งแก้ข้อมูลกลางที่กระทบรายการอื่น การลงทะเบียนทีมใช้ทีมของเจ้าของรายการตามโครงสร้างเดิม

รายการเดิมคง `owner_id` เดิม การติดตั้งไม่ได้โอนรายการจากบัญชีอื่น ตรวจเจ้าของเดิมได้ด้วยคำสั่งอ่านอย่างเดียว:

```sql
select u.email, count(*) as competitions
from public.fm_competitions c join auth.users u on u.id=c.owner_id
group by u.email;
```

รายการของ `arreef04@gmail.com` ยังคงเป็นของบัญชีนั้น หน้าสาธารณะยังคงแสดงเฉพาะข้อมูลการแข่งขันที่เจ้าของเปิดเผย ไม่เปิดเผยรายชื่อสมาชิกหรืออีเมล

## ตรวจสอบ

`npm test` ครอบคลุมเจ้าของ ผู้ดูแลร่วม บุคคลภายนอก อีเมลยังไม่ยืนยัน การรับคำเชิญ การถอนสิทธิ์ การพยายามยกระดับสิทธิ์ การแยกข้อมูลรายการและคลังทีม ตลอดจน RPC รายชื่อ/โปรแกรม/ผล OBS และการอ่านสาธารณะ

`npm run test:e2e` ตรวจสมัครสมาชิก หน้าผู้ดูแลร่วม และงานจัดการแข่งขันเดิมบนเบราว์เซอร์
